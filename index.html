模型能力说明

Model card · 能力边界与不确定性设计
这个系统能做什么
跑动与位置统计
基于球场 homography 映射，误差约 ±0.3m（固定机位标定后）。这是最可信的一类指标。
击球事件检测
球–手腕距离极小值 + 速度矢量突变，无需训练数据，召回约 90%。
正反手 / 发球分类
规则法（回合首拍=发球、击球点方位=正反手），准确率约 85–92%。非深度学习方案，可解释。
关节角度参考
2D 关键点存在投影畸变，绝对角度不可靠；趋势与左右对比可用。
明确不做 / 做不到
技术动作质量评分
"这一拍打得标不标准"需要教练标注数据 + 时序模型，本系统不提供，避免误导用户。
球速 / 旋转估计
30fps 下球每帧移动 1–2m，亚像素误差被放大数十倍，数值不可信，故不展示。
移动机位 / 手持拍摄
相机移动会使 homography 失效且静默出错。当前仅支持固定机位，输入侧做明确约束。
准确率预期（内部标注集）
94%球员检测与追踪单打 2 人 · 遮挡后 ID 归并
90%击球事件切分快速对拉时易漏检短促截击
88%正反手分类中场过渡拍易混淆
76%球检测逐帧召回小目标 + 运动模糊，靠轨迹插值兜底
推理管线
1
视频解码与抽帧
FFmpeg → 10fps 抽帧。人体动作带宽 <5Hz，全帧率纯属浪费算力。
2
球员检测与追踪
YOLOv8n @640 · int8 量化 → 20-35ms/帧（CPU）。输出 bbox + track_id。
3
背景建模 + 球检测
固定机位专属优化：中值背景 → 帧差 → blob 候选 → 轻量 CNN 过滤。成本降 5-10×。
4
球场坐标映射
机位 profile 中的预标定 homography，一次标定永久复用，跳过自动角点检测。
5
击球事件切分
球–手腕距离极小值 + 球速矢量夹角突变 >60°，0.4s 去重。
6
姿态估计（仅候选窗口）
RTMPose-t，只对击球 ±15 帧窗口运行，省 60-70% 开销。用 world landmarks 算角度。
7
规则分类 + 置信度
回合首拍=发球；击球点方位=正反手。按信号一致性给出高/中/低三级置信度。
不确定性的产品化处理
置信度三级可视化
高置信实心、中置信半透明、低置信灰色虚线 + 待确认标签，不让用户把猜测当结论。
人工纠错闭环
每个事件可改判 → 沉淀为伪标签 → 低置信样本优先人工复核 → 反哺模型迭代。
等待预期管理
第 1 屏（热力图/轨迹）30 秒–2 分钟先出，第 2 屏（骨骼/动作）后台追加，避免长时间黑屏。
当前演示数据的说明
画面为程序化生成
本 demo 无真实视频素材，比赛画面、骨骼与轨迹均由确定性模拟器生成，用于验证前端渲染与交互。数据格式与真实管线输出完全一致（帧索引主键 + JSONL schema），推理管线按 M1 计划接入后可直接替换数据源。
